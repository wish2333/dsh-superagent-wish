# 06: 策略版本与并发上限

**What to build:** 每个工作单元记下开它时的策略版本。规则变了只通知受影响且还在跑的工作单元，不撤销授权。已结束的工作单元在恢复前重新校验。执行者的并发槽位可配置，wish 的追问不占槽。

**Blocked by:** 02

**Status:** resolved

- [ ] 开工作单元时记下当时的策略版本
- [ ] 规则变化只通知受影响且未结束的工作单元
- [ ] 规则变化不撤销正在跑的工作单元的授权
- [ ] 已结束的工作单元恢复前重新校验，通不过就保持结束
- [ ] 执行者槽位上限可配置，默认 2
- [ ] 启发者不占槽位
- [ ] wish 的追问不占槽位
- [ ] 槽位满时新派发排队，不报错
- [ ] 同一目录上不会同时跑两个执行者

**Notes:** 照原型 `src/policy.ts` 的 `policyVersion` 与 `revalidate`。个人使用里规则几乎不变，这一票的日常收益接近零，做它是为了规则真变时活不会无声复活。

---

## Answer

策略版本是规则与事件源配置的哈希，不是计数器：同样的规则得同样的版本，重启不变，改规则就变。建活时写进授权。规则变化只通知未结束且仍停在旧版本的工作单元，不撤销授权。已结束的工作单元被追问前按当前策略重新校验。执行者槽位默认 2、可配 1–16，启发者与 wish 的追问不占槽；槽满时派发排队并在报告、停止、回合结束或重启时接上。
