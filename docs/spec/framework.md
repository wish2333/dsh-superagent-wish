# AI 服务器元框架

本文件是这台机器 AI 工作区的设计规格。它描述"这套系统应该是什么"，不描述"怎么实现"。

实现细节、能力状态、工具路径见 `~/.agents/ENVIRONMENT.md` 和 `~/.agents/SKILLS.md`。

本仓库只实现运行时层的 Partner 和 Worker；资产层、能力层是这台机器上已有的东西，本插件引用，不重建。需求编号见 `../REQUIREMENTS.md`。

---

## 目的

构建一套元框架，让后续大部分 AI 相关工作都能在此基础上展开，而不是每次从零搭建。

**唯一检验标准**：某一天因此变好了。

---

## 四层结构

工具层由四个子层组成，从稳定到可替换排列：

```
资产层 ──► 能力层 ──► 组合层 ──► 运行时层
  最稳定                            最易替换
```

越靠左越稳定，越靠右越容易换。**换运行时时，资产层和能力层不动；换能力时，资产层不动。真正需要针对运行时配置的，只有组合层。**

---

## 资产层

**定义**：知识和技能的存放地。Agent 不直接修改这里的结构，只通过约定接口读写。

**内容**：

| 资产 | 路径 | 格式 | 写入方 |
|---|---|---|---|
| 人工知识库 | `~/AI/vaults/` | Obsidian Markdown | 人 |
| 技能库 | `~/AI/repos/skill-dev` | SKILL.md 规范 | 人 + Agent 协作 |
| 机器记忆 | `~/AI/memory/hindsight/` | Hindsight bank | Agent（自动写入） |

**设计原则**：只用公开格式（Markdown、SKILL.md 规范）。不依赖特定 harness 或运行时。任何兼容 Agent Skills 规范的工具都能加载这里的技能；任何兼容 Hindsight MCP 的工具都能读写记忆。

**当前状态**：
- 人工知识库：已建，Verysync 同步，Obsidian 管理。
- 技能库：已建，git 管理，软链安装到 `~/.agents/skills/`，并入五个产品目录。
- 机器记忆：Hindsight 容器运行中（bank: `wish`、`tool-layer`）。写入通过会话结束钩子（S1）触发；**已知缺口：recall（读取注入）未接入，记忆只进不出**。

---

## 能力层

**定义**：Agent 可以调用的"手"。以 MCP 或技能（SKILL.md）形式暴露，不绑定特定运行时。

**内容**：

| 能力 | 接口形式 | 落点 | 状态 |
|---|---|---|---|
| 浏览器操作 | 技能 + CDP | browser-harness / bsk | 就位 |
| 记忆读写 | MCP | `<hindsight-service>/mcp/` | 写入就位；读取未接入 |
| 文档处理 | 技能 | pdf/pptx/xlsx/docx | 就位 |
| 知识库检索 | 未建 | — | 缺口 |

**设计原则**：能力的实现（服务、脚本、CLI）对调用方透明。调用方只看 MCP 端点或技能名称，不关心背后是什么。

**当前缺口**：
- Hindsight recall 的触发时机和注入路径未设计。
- `~/AI/vaults/` 内容无法被 Agent 检索（没有检索层）。

---

## 组合层

**定义**：声明 Worker 可以访问哪些能力。这是唯一需要针对运行时定制的东西。

**职责**：在资产层/能力层（稳定）和运行时层（可替换）之间建立显式接缝。换运行时时，只改这里，不改资产层和能力层。

**当前状态**：规格已定。见 `./composition-spec.md`（规格说明）和 `./composition.yaml`（机器可读配置）。

Worker 类型：启发者（discoverer）、执行者（implementer）。两类 Worker 的差别全部落在 preset 的工具白名单上，见上述文件。`../impl/plugin-manifest.md` 列出本插件用到的 DSH Host 服务。

---

## 运行时层

**定义**：任务的进入、分派和回报。**不存放知识。**

**职责**：接收来自人或事件的输入，决定派给谁、怎么派，把结果带回给人。

**当前实现**：DeepSeek Harness 插件（本仓库）。
- 任务入口：你的消息
- 分派：`ctx.sessionController.create({ agentPreset })`，每个 Worker 一个独立会话和工作目录（R28）
- 派发前由 Partner 暂停等确认；DSH 无强制机制
- 已知限制：无 Watchdog，Worker 卡住时靠自报

**当前状态**：协作模式规格见 `./interaction-spec.md`；派发技术方案见 `../impl/superagent-impl.md`。

**待设计**：
- 文件入口的巡查周期和文件夹名单（依赖 cron，后续接入）。
- 记忆层的跨会话延续。
- Watchdog 的实现方式。

---

## 层间契约

| 调用方 | 被调用方 | 契约形式 |
|---|---|---|
| 运行时层 | 组合层 | Worker 读取能力清单，确定可用工具 |
| 组合层 | 能力层 | MCP 端点 + 技能名称（已有标准） |
| 运行时层 | 资产层 | 技能加载（SKILL.md）；记忆读写（Hindsight MCP） |
| 能力层 | 资产层 | 记忆写入 Hindsight bank；技能正文在 skill-dev |

---

## 设计原则

来自原始调研文档（已归档，不在本仓库），这里是约束，不是建议：

1. **资产用公开格式，任务跑在可替换的运行时上。** 资产层不依赖任何特定 harness。
2. **路由只分派，不执行。** Partner 不亲自跑工具，只安排任务。
3. **换运行时只改组合层。** 资产层和能力层对运行时的变化免疫。
4. **工具留下的条件只有一个：某一天变好了。** 这是每个新增组件的准入标准。
